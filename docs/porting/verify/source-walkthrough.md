## Global
- Auth: `/login` (below). Unauthenticated owner/staff routes redirect to /login (history state `from`). `/` redirects to `/admin` when signed in.
- Roles: owner, admin (`_owner` guard: /admin/*, /p/:code/present); check-in staff (`_staff`: /admin/checkin/*). Staff opening owner pages is redirected to `/admin/checkin` (observed: loading `/admin` as door staff hung the browser tab in dev; `/admin/checkin/...` direct works). Other wrong role: Forbidden screen "You don't have access to this page" / "Your role (X) can't open this part of the workspace. Ask the workspace owner if you need access." / button "Go to dashboard".
- Admin shell: left sidebar "CreatorCrowdHub" logo link `/admin`, "Toggle Sidebar" button; nav Dashboard `/admin`, Events `/admin/events`, Guests `/admin/contacts`; bottom: Settings `/admin/settings`, Design system `/design-system`, "Dark mode" toggle button, primary "CREATE EVENT" (`/admin/events/new`); footer user button (avatar "CB", "Clara Bennett", "Clara Coaching") opening a menu: "Signed in as / Clara Bennett / email / Owner", Theme Light/Dark/System (tick on current), Settings, Sign out. Browser title `★ Events`.
- Public pages: skip link "Skip to content" (#main), footer "Powered by CreatorCrowdHub".
- Dev-only fixture galleries: `/dev/errors`, `/dev/guest`.
- API CSRF: mutating `/site-api` calls need header `X-Requested-With: ezy-events` (else 403 "Missing or invalid X-Requested-With header.").
